CroXML Verify

Jedini validator u Hrvatskoj koji provjerava e-Račune, fiskalizaciju, UBL, XRechnung i XAdES potpise — u jednom alatu. Tri razine validacije. Nula kompromisa.

UBL 2.1 + EN 16931 XRechnung + ZUGFeRD PEPPOL BIS 3.0 XAdES digitalni potpis
Problem koji rješavamo
Svaki odbijeni e-Račun košta vrijeme, novac i živce. CroXML Verify ih eliminira prije slanja.

Odbijeni dokumenti

FINA i Porezna odbijaju e-Račune s minimalnim greškama — krivi OIB format, nedostaje CustomizationID, PDV kalkulacija ne štima za 0.01 EUR.

Sati za debug

Bez validatora, tražite grešku u 500+ linija XML-a. S validatorom — točna linija, točno pravilo, prijedlog za fix. Sekunde umjesto sati.

N alata za N formata

UBL imate ovdje, XRechnung tamo, fiskalizaciju negdje treće. CroXML Verify je jedan alat za sve — HR i DE tržište.

Tri razine validacije
Svaki dokument prolazi trostruku provjeru — isto kao što FINA i Porezna rade, ali prije slanja.
1

XSD Schema

Strukturalna provjera XML-a prema OASIS UBL 2.1 specifikaciji. Svaki element, atribut i namespace.

2

EN 16931 pravila

40+ poslovnih pravila: BR-01 do BR-26, PEPPOL BIS, HR CIUS. Matematička ispravnost PDV-a.

3

HR/DE pravila

OIB checksum (ISO 7064), datum konzistentnost, valuta podudaranje, DE §14 UStG.

e-Račun (UBL 2.1)

Potpuna validacija prema europskoj normi EN 16931 i hrvatskom CIUS profilu. Podržava tipove: 380 (račun), 381 (odobrenje), 383 (terećenje), 386 (predujam).

XRechnung + ZUGFeRD

Za tvrtke koje fakturiraju u Njemačkoj. CII format za B2B (XRechnung) i hibridni PDF+XML (ZUGFeRD 2.2) za kompatibilnost s DATEV-om.

XAdES digitalni potpis

Provjera XML potpisa na dokumentima iz GovExport sustava — AgroHealth, TuristPrijava, InventoryLedger. SHA-256 hash za integritet.

Fiskalizacija

Verifikacija ZKI/JIR kodova, certifikat provjera (.p12), SOAP envelope validacija prema CIS specifikaciji Porezne uprave.

Ključna poslovna pravila (EN 16931)
40+ pravila koja validator provjerava automatski.
  • BR-01 Broj računa mora postojati
  • BR-02 Datum izdavanja je obavezan
  • BR-03 Tip dokumenta mora biti valjan (380, 381, 383, 386...)
  • BR-04 Valuta — ISO 4217 (3 slova: EUR, HRK, USD)
  • BR-05→26 Prodavač/kupac podaci, iznosi, stavke, PDV
  • BR-CO-10 Zbroj PDV-a po stopama mora odgovarati ukupnom PDV-u
  • BR-S-08 Standardna PDV stopa mora biti pozitivna
  • PEPPOL-R004 CustomizationID mora postojati za PEPPOL mrežu
  • HR-CIUS OIB format: 11 znamenki, ISO 7064 MOD 11-10 checksum
  • PROP-06 TaxInclusive iznos mora odgovarati Payable iznosu
  • PROP-07 Valuta mora biti konzistentna na svim razinama dokumenta
  • DE-§14 Steuernummer obavezan, Leistungsdatum za DE fakture

2. e-Račun API (za integratere)

POST /eracun/api/create/
Kreiraj e-Račun — prolazi automatsku trostruku validaciju prije slanja
{
  "invoice_number": "R-2026-001",
  "doc_type": "380",          // 380=račun, 381=odobrenje
  "issue_date": "2026-03-29",
  "issuer_oib": "12345678901",  // ISO 7064 checksum
  "recipient_oib": "98765432100",
  "items": [{
    "description": "Konzultacije",
    "quantity": 10,
    "unit_code": "HUR",
    "unit_price": 100.00,
    "tax_rate": 25,
    "tax_category": "S"
  }],
  "auto_send": true  // validira + šalje odmah
}
GET /eracun/api/status/<uuid>/
Provjeri status validacije i slanja
{
  "status": "accepted",  // draft → validating → valid → sending → sent → accepted
  "fina_uuid": "550e8400-e29b...",
  "errors": [],
  "warnings": ["PROP-02: Datum izdavanja je u budućnosti"]
}
POST /eracun/sukladnost/run/
Pokreni 5 testova sukladnosti (simulira provjeru Porezne uprave)
// 5 testova:
TS-01: Certifikat (.p12) — validnost, istek, subject
TS-02: UBL generiranje — CIUS elementi, dobavljač, kupac
TS-03: XSD + EN 16931 — schema + 40 pravila
TS-04: Fiskalizacija — CIS ping, fiskalni certifikat
TS-05: Inbox — prijem e-Računa, Posrednik konekcija
